# MediaServer v19.0 migration evidence

## Source decision

Debian 13 Trixie does not package the Jellyfin server. Its package search has
one name match, `python3-jellyfin-apiclient-python`, which is a client library.
The appliance therefore uses Jellyfin's official signed stable APT repository
for Trixie. The upstream index publishes and retains the compatible
`10.11.10+deb13` and `10.11.11+deb13` server, web, and metapackage builds.

The appliance verifies Jellyfin signing-key fingerprint
`4918 AABC 486C A052 358D 778D 4902 3CD0 1DE2 1A7B`, records the installed
version and source identity, and requires those values before its updater will
query or change packages. Version `10.11.11+deb13` corresponds to official tag
`v10.11.11`, commit `1fbd8739292cce610231be93daf43368733edf63`.

Evidence endpoints:

- Debian Trixie package search:
  `https://packages.debian.org/search?keywords=jellyfin&searchon=names&suite=trixie&section=all`
- Jellyfin Trixie package index:
  `https://repo.jellyfin.org/debian/dists/trixie/main/binary-amd64/Packages`
- Jellyfin stable Debian artifacts:
  `https://repo.jellyfin.org/files/server/debian/latest-stable/amd64/`

still returned HTTP 503. Product loop 1 retains the health gate and retries
only that startup request on transient failure for at most four minutes; a
terminal failure includes the final 100 Jellyfin log lines.

## Deferred issues

- MEDIUM: Hardware-accelerated transcoding varies with host GPU, device
  passthrough, and Debian drivers. The exact runtime checks discovery and
  playback metadata without claiming host-specific acceleration.
- MEDIUM: Direct Jellyfin HTTPS on port 8920 requires an administrator-provided
  certificate. The appliance TLS proxy on port 12322 is tested instead.
- LOW: Administrator authentication and web serving use the real APIs but do
  not automate browser rendering.
